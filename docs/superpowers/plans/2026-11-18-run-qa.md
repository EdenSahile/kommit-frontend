# Skill /run-qa : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Créer le skill `/run-qa` qui teste seul une US entière sur le lien de déploiement DEV, en 2 passes, et rend un rapport avec captures et KO classés par gravité.

**Architecture:** 3 fichiers. Un hook shell (`guard-e2e-qa.sh`) bloque la modification des e2e trackés par git pendant le QA, activé par le fichier marqueur `/tmp/qa-session-active`. Un subagent (`qa-explorer`) fait la passe 2 d'exploration navigateur dans son propre contexte. Un skill (`run-qa/SKILL.md`) orchestre : il lit les tickets `TO TEST` depuis Notion, lance la passe 1 (e2e scriptés), délègue la passe 2, et compile le rapport.

**Tech Stack:** Bash + Python 3 pour le hook, markdown pour le skill et l'agent, Playwright (scripts `test:e2e:qa:*` existants) pour la passe 1, MCP Playwright pour la passe 2, MCP Notion pour lire les tickets.

**Spec:** `docs/superpowers/specs/2026-11-18-run-qa-design.md` (ticket KOM-15 : https://app.notion.com/p/ddee39355d3083ecab8a81623cbec754)

## Global Constraints

- **Le QA ne tourne jamais sur `localhost`** (RM2). Le lien déployé vient de `.env.qa` via `QA_BASE_URL` ; si `.env.qa` manque, le workflow s'arrête et demande à l'utilisateur de le créer.
- **`.env.qa` est illisible par Claude** : le hook global `block-env-read.sh` bloque la lecture de tout `.env*` sauf `.env.example`. Le skill vérifie son **existence** (`test -f .env.qa`), jamais son contenu.
- **Garde-fou 1 (RM5)** : interdiction de modifier un test e2e **existant**. Bloqué par hook, pas seulement par consigne (contrainte technique 7).
- **Garde-fou 2 (RM6)** : interdiction de modifier le code de prod (`src/`). Par consigne seulement, dans le skill **et** dans le subagent (contrainte technique 8).
- **Limites (RM4)** : passe 2 plafonnée à 15 cas, avec au moins 1 cas par zone de l'app ; durée totale plafonnée à 20 minutes, au-delà le workflow rend le rapport partiel.
- **Les règles métier de référence sont celles des tickets de tâche** (KOM-06, KOM-07), pas du ticket d'US.
- **Rules d'écriture du repo**, `.claude/rules/ecriture-skills-et-agents.md` : `## Entrée` puis `## Sortie` en **puces**, juste après le frontmatter, le « comment » après un `---` ; un skill est nommé par un verbe d'action, un agent par un nom en `-er` ; la condition de déclenchement s'écrit « Utiliser quand » ; **aucune séquence `: ` dans une valeur de frontmatter non quotée**.
- **Gestionnaire de paquets : `pnpm`**, jamais `npm` ni `npx`.
- **Pas de merge sans accord explicite** de l'utilisateur pour cette PR précise.

## Review Focus

Les 5 cas que la spec implique sans qu'aucun test ne les exerce, du plus probable au moins probable. Chaque ligne a son test ajouté à la tâche qui porte le code.

1. **Marqueur oublié après un crash** : si `/run-qa` plante avant son nettoyage, `/tmp/qa-session-active` reste, et toute édition d'un e2e est bloquée silencieusement dans toutes les sessions suivantes. Attendu : le hook ignore un marqueur de plus de 60 minutes (le QA est plafonné à 20 min). → Tâche 1.
2. **Hook appelé depuis un autre dossier** : un `git ls-files e2e/` lancé hors du repo rend une liste vide, et le garde-fou est éteint sans bruit. Attendu : le hook se repère sur `$CLAUDE_PROJECT_DIR` et non sur le dossier courant. → Tâche 1.
3. **Commande Bash qui ne fait que lire ou lancer les e2e** (`cat e2e/signin.test.ts`, `pnpm test:e2e:qa:seq > sortie.txt`) : si le hook la bloque, la passe 1 ne peut pas tourner du tout. Le 2e cas est le piège : la redirection `>` ressemble à une écriture et `test:e2e:qa` contient le mot `e2e`. Attendu : lecture et exécution toujours autorisées, seule l'écriture **d'un fichier e2e tracké** est bloquée. → Tâche 1.
4. **Chemin absolu contre chemin relatif** : `Edit` passe un `file_path` absolu, `git ls-files` rend un chemin relatif au repo. Attendu : les 2 formes sont reconnues comme le même fichier. → Tâche 1.
5. **Création d'un nouvel e2e pendant le QA** (RM8) : le garde-fou ne doit pas empêcher le workflow d'écrire les tests manquants. Attendu : un fichier e2e non tracké par git passe, en `Write` comme en redirection Bash. → Tâche 1.

Le seul fichier testable isolément. Modèle à copier : `.claude/hooks/protect-tests.sh` (même structure, même usage de `python3 -I`, même sortie `exit 2` + message sur stderr), en remplaçant le test de variable d'environnement par le test du fichier marqueur.

**Files:**

- Modify: `.claude/settings.json:8-18`, ajouter le hook dans le tableau `hooks.PreToolUse[0].hooks`, à côté de `protect-tests.sh`, sous le même matcher `Edit|Write|MultiEdit|NotebookEdit|Bash`

**Interfaces:**
- Consumes: rien (premier fichier).
- Produces: le contrat que le skill de la tâche 3 et l'agent de la tâche 2 doivent respecter :
  - **marqueur** : `/tmp/qa-session-active`, créé par `touch` au début du QA, supprimé par `rm -f` à la fin ;
  - **durée de validité** : 60 minutes après le `mtime` du marqueur, au-delà le hook laisse tout passer ;
  - **périmètre bloqué** : les fichiers de `e2e/` **trackés par git** uniquement ;
  - **sortie en cas de blocage** : `exit 2`, message sur stderr.

*Pourquoi `/tmp` et non le scratchpad de session* : le marqueur doit être visible depuis le process du hook et depuis une 2e session Claude (le test d'acceptation « garde-fou 1 » du ticket envoie le prompt de modification pendant que le QA tourne). Un chemin de scratchpad est propre à une session, donc invisible pour l'autre.

- [ ] **Step 1: Écrire le hook**

En-tête de commentaire sur le modèle de `protect-tests.sh` (numéroté, ce que fait chaque étape). Puis l'algorithme, que la signature ne détermine pas :

```bash
#!/bin/bash
# 1. Vérifier qu'une session de QA est en cours
[ -f /tmp/qa-session-active ] || exit 0
# Marqueur périmé (plus de 60 min) : une session de QA a planté sans nettoyer.
[ -n "$(find /tmp/qa-session-active -mmin +60 2>/dev/null)" ] && exit 0

# 2. Lister les e2e trackés par git, depuis le repo et non le dossier courant
cd "$CLAUDE_PROJECT_DIR" || exit 0
TRACKED=$(git ls-files e2e/)
[ -z "$TRACKED" ] && exit 0

# 3. Bloquer l'écriture sur un fichier tracké
TRACKED="$TRACKED" python3 -I -c '
import json, os, re, sys
tracked = set(os.environ["TRACKED"].split())
d = json.load(sys.stdin)
tool = d.get("tool_name", "")
inp = d.get("tool_input") or {}
writes = re.compile(r"(\bsed\s+-i|\bperl\s+-i|\brm\b|\bmv\b|\bcp\b|\btee\b|>|\bgit\s+(checkout|restore|rm|mv)\b|\btruncate\b)")
target = ""
if tool in ("Edit", "Write", "MultiEdit", "NotebookEdit"):
    path = inp.get("file_path") or inp.get("notebook_path") or ""
    if any(path == t or path.endswith("/" + t) for t in tracked):
        target = path
elif tool == "Bash":
    cmd = inp.get("command", "")
    if writes.search(cmd):
        # Le token doit etre un chemin autonome : la borne de gauche ecarte le
        # "e2e" de "pnpm test:e2e:qa:seq", colle a un ":".
        mentioned = re.findall(r"(?:^|[\s\x27\"=])(e2e(?:/[\w./-]*)?)", cmd)
        if any(m in tracked or m in ("e2e", "e2e/") for m in mentioned):
            target = cmd
if target:
    print("Interdit pendant une session de QA (/run-qa) : tu ne peux pas modifier un test e2e existant (RM5). "
          "Tu peux seulement CREER de nouveaux fichiers e2e. Si ce test est un faux negatif, ne le corrige pas : "
          "note-le dans le rapport QA et laisse l utilisateur decider. Cible bloquee : " + target[:200], file=sys.stderr)
    sys.exit(2)
'
```

Rendre le fichier exécutable : `chmod +x .claude/hooks/guard-e2e-qa.sh`.
