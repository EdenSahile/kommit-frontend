## Hors périmètre UI

| RM | Pourquoi elle ne se teste pas depuis l'app |
|----|--------------------------------------------|
| RM18/RM19 (INTERNAL_ERROR) | Nécessite de simuler une panne serveur (5xx, timeout). Un utilisateur ne peut pas provoquer ça depuis l'app. |
| RM2-backend (route protégée 401) | Vérifiable uniquement par appel API direct, sans passer par l'interface. |
| RM20 (prénom d'espaces refusé par le serveur) | Inatteignable depuis l'interface : RM33 grise le bouton quand le prénom ne contient que des espaces, donc la requête ne part jamais. |

## Cause commune des 12 tests rouges

**Cold start + rate limiting.** Le backend Render (free tier) dort entre les appels. Les 2-3 premiers tests échouent parce que le backend met plus de 5s à répondre (CA1, CA2, CA6). Une fois réveillé, le rate limiter du backend refuse les requêtes d'authentification quand la suite crée 10+ comptes en séquence rapide (429, traduit en INTERNAL_ERROR côté frontend). Les 9 autres rouges viennent de là.

Pistes pour rendre l'environnement apte : réveiller le backend avant la suite (un curl de warmup), augmenter la limite de rate limiting en DEV, ou ajouter un retry avec attente dans `createAccountViaApi`.
