## Hors périmètre UI

| RM | Pourquoi elle ne se teste pas depuis l'app |
|----|--------------------------------------------|
| RM18/RM19 (INTERNAL_ERROR) | Nécessite de simuler une panne serveur (5xx, timeout). Un utilisateur ne peut pas provoquer ça depuis l'app. |
| RM2-backend (route protégée 401) | Vérifiable uniquement par appel API direct, sans passer par l'interface. |
| RM20 (prénom d'espaces refusé par le serveur) | Inatteignable depuis l'interface : RM33 grise le bouton de création quand le prénom ne contient que des espaces, donc la requête ne part jamais et la validation serveur n'est pas atteinte. Corrigé après coup, ce rapport la comptait à tort comme couverte. |

## Faux négatifs à corriger par l'utilisateur

| Test e2e | Pourquoi c'est le test qui a tort |
|----------|-----------------------------------|
| CA17, SM-7, CA16 (signin.test.ts) | `createAccountViaApi` reçoit un 429 (rate limit) du backend Render après les créations de comptes précédentes. L'app fonctionne, c'est la cadence des tests séquentiels qui déclenche le rate limiter. |
| CA5, RM31 (signout.test.ts) | `signUpViaUi` échoue car le signup reçoit « Une erreur interne est survenue » (le rate limiter renvoie 429, que le frontend traduit en INTERNAL_ERROR). La redirection vers `/` n'arrive jamais. |
| CA8 (signup.test.ts) | Même cause : le signup échoue avec un 429 rate-limité, l'URL reste sur `/signup`. |
| CA9 (signup.test.ts) | `createAccountViaApi` reçoit un 429 avant même de pouvoir tester l'unicité email. |
| RM3 (toast.test.ts) | `signUpViaUi` échoue, même pattern 429. |
| RM25 (toast.test.ts) | `createAccountViaApi` reçoit un 429. |
| RM21-espaces (signup-email-uniqueness.test.ts) | `createAccountViaApi` reçoit un 429 lors de la création du compte préalable. |

**Cause commune** : le backend Render applique un rate limit sur les endpoints d'authentification. Quand la suite e2e crée 10+ comptes en séquence rapide, les derniers appels sont refusés avec un 429. Pistes de correction : espacer les tests, augmenter la limite en DEV, ou ajouter un retry avec attente dans `createAccountViaApi`.
